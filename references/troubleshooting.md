# 常见问题与故障排查（troubleshooting）

本文档汇总使用「多表人员信息汇总助手」时的常见报错、出现原因以及针对性解决方案。

---

## 常见报错与处置速查表

| 报错现象 / 提示信息 | 根本原因 | 推荐处置方式 |
|---|---|---|
| **`不支持的文件类型 .xls`** 或 **`检测到旧版二进制 .xls`** | 该文件是 Excel 97-2003 的真·二进制复合文档（BIFF/OLE 格式），当前环境未安装可选依赖 `xlrd`。 | **两条路径二选一：**<br>1. （推荐、免安装）用 Excel/WPS 打开该文件，直接点击“另存为”，保存为 `.xlsx` 格式后再处理；<br>2. 运行 `pip install xlrd` 安装本地解析库后重试。 |
| **`压缩包内未找到 xl/workbook.xml 或 content.xml`** | 该文件虽然扩展名为 `.xlsx` 或 `.ods`，但内部并非合规的工作簿结构（例如被误改名的 `.zip`、`.docx` 或已损坏文件）。 | 确认文件是否能够被常规 Office 软件正常双击打开；确认扩展名是否与文件真实类型一致。 |
| **`无法识别 CSV 编码`** | 文本编码超出内置识别链（`utf-8-sig / utf-8 / gb18030 / gbk / big5`），或文本包含严重乱码。 | 用 Excel 或记事本打开该 CSV，另存为“带有 BOM 的 UTF-8（CSV UTF-8）”格式。 |
| **`文件中没有可读取的数据行`** | 目标工作表为空，或者数据未存放在首个 Sheet。 | 本 Skill 默认只解析工作簿的**第一个工作表**。若有效数据位于其他 Sheet，请在 Excel 中将该 Sheet 拖动至首位或单独另存为一个文件。 |
| **读到的列比预期少** | 输入表中存在纯空格填充列或 `number-columns-repeated` 展开后的空白占位列。 | 引擎为了保障产出报表的干净度，会自动过滤**整列全为空值**的无意义填充列。请核实该列源文件是否本身就无实际数据。 |
| **`含 XML DTD/实体定义，出于安全考虑拒绝解析`** | 输入的 XML/SpreadsheetML 文件中包含 `<!DOCTYPE` 或实体引用声明，触发了引擎的 XML 实体注入防护。 | 正常系统导出的 Excel 数据不包含此类标签。建议使用 Excel/WPS 重新打开并另存为干净的 `.xlsx`。 |
| **推荐关联键一致率都很低（例如 < 30%）** | 各表人员重合度确实极低；或者关联列虽同义但包含了大量部门/职位等混杂文字；或者选错了关联列。 | 查看 `profile.json` 确认采样的数据行，并在编辑 `plan.json` 时手动指定真正对应的业务关联列（如强制指定“工号”或“身份证号”）。 |
| **未匹配记录明显偏多** | 姓名列包含生僻异体字、错别字、跨系统导出的不同系统前缀（如 `NO.101` vs `101`）。 | 打开 `未匹配记录` Sheet，重点查看最后一列的**“最相近候选”**推荐，快速定位错别字或前后缀规律。 |
| **`指定了 --backend openpyxl，但环境未安装`** | 命令行强制指定了 `--backend openpyxl`，但当前 Python 环境未安装该三方库。 | 运行 `pip install openpyxl`；或者去掉该参数改用默认的纯标准库后端 `--backend stdlib`。 |
| **合并结果中部分单元格数值末尾多了 `.0`** | 浮点数在跨系统序列化时的常见偏差。 | 引擎内部已针对纯数字字符（如手机号、工号）执行了 `_num_text` 自动截断规范化；若仍有罕见浮点显示，可在 Excel 中批量设置单元格为“文本”或“常规”格式。 |
