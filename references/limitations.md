# 风险边界与不支持场景（limitations）

1. **不支持 PDF / 图片 / 扫描件**：请先转为 Excel/CSV。
2. **旧版二进制 `.xls`（BIFF/OLE 复合文档）需要可选依赖 `xlrd`**：
   未安装时给出两条出路——① 用 Excel/WPS 另存为 `.xlsx`（推荐，零依赖）；
   ② `pip install xlrd` 后重试。**被改名成 `.xls` 的 HTML 表格 / Excel 2003 XML /
   分隔符文本会自动按真实内容读取**（这是真实系统导出最常见的情况，已内置支持）。
3. **不支持加密文件**：打开需密码的 xlsx/xls 请先解密（含密码的 `.xls` 交给 xlrd 也会报错）。
4. **只读首个工作表**：`.xlsx/.xlsm/.ods` 只取第一个工作表；多 sheet 需分别汇总时请拆成多个文件。
5. **HTML 只取第一张 `<table>`**：`colspan` 会展开、`rowspan` 不展开（并在该处留下空单元格）；
   `script/style` 内容被忽略。
6. **整列全空的填充列会被丢弃**：稀疏表格/`number-columns-repeated` 产生的大量空列不会带进结果，
   因此读回的列数可能少于源文件列数。
7. **不判断数据对错**：同字段多表取值不一致时，两列都保留 + 行标记 + 日志清单，
   由用户做业务决策（例：李四两个手机号以哪个为准，Skill 不选边）。
8. **不承诺一次合并永远正确**：`合并日志` sheet 是责任记录；
   未看日志直接使用结果，后续数据问题的责任边界在用户侧。
9. **中文同名天然歧义**：纯姓名合并无法区分同名同姓两人；有工号请优先用工号做键。
10. **别称/曾用名不自动等同**：`张三（曾用名张小三）` 这类后缀会被剥离后比对，
    但两个完全不同的名字不会被判定为同一人。
11. **表头须规整**：要求单行表头；合并单元格式多级表头、表头上方有多余标题行且
    10 行内定位不到表头的，需用户先整理。
12. **资源上限**：单文件 200MB、单表 20 万行；压缩包内单个 XML 解压上限 64MB；
    超限请分批。
13. **输出面向"人看"**：不做严格 schema 校验、不做导入 HR 系统/数据库的格式适配。
14. **冲突检测依赖列名语义归一**：同义列名（手机 / 联系电话 / 联系方式 等）会被归为同一逻辑字段
    来比对取值；非常规命名（如"微信"与"微信号"并列）可能不被识别为同一字段。
    因此日志"未报冲突"≠"一定无冲突"，关键字段建议人工抽查。
15. **读取时统一做 NFKC 归一化**：全角数字/字母/括号会被转为半角（对手机号、日期等混排有用），
    该归一化也会作用在**表头**上——所以用本工具二次读回自己产出的文件时，
    列名会显示为半角括号 `(来源:xxx)`；交付给用户的 xlsx 文件本身按写入原样保留全角括号。
16. **结果表固定附带末列 `数据状态`**：值为 `完整匹配` / `部分缺失（缺：…）` / `冲突：…` 等，
    可直接按该列排序筛选，快速定位需要人工核对的记录。
17. **格式验证的诚实说明**：`.xlsx/.csv` 用本仓示例数据与写后读回校验；
    `.ods`、HTML 伪 `.xls`、Excel 2003 XML 用**按格式规范现场构造的测试夹具**验证
    （`tests/test_people_merge.py`、`selftest` 阶段 2）；真·二进制 `.xls` 依赖官方 xlrd，
    本仓库不含该格式样表，故仅在无依赖时验证"指引提示"分支。
